## App changes

- Conversations have persistent identities before the first Send. Each keeps its
  workspace and preferred model; the default model applies to new conversations.
- Draft text and attachments save in order before switching, Back, and Quit.
  A failed save keeps the app open with an error. Saved v1–v6 stores migrate to v7
  with a backup before the first migrated write.
- Choosing or creating a workspace opens another conversation. Cancellation and
  Back preserve the originating conversation. Workspace creation recovery does
  not repeat folder creation.
- Other conversations remain browsable during a task. The running-task banner
  opens its owner or stops it. An approval can stay pending while you browse;
  its owner has a Review action and a direct Stop control. Background approvals
  leave the viewed chat accessible. One task executes at a time. Undo, permissions,
  research notes, and file actions retain explicit conversation/workspace scope.
- Verified imports reuse cached files, prefer hard links, and copy across
  filesystems when necessary. Desktop symlinks resolve to their source files.
  A pinned split model accepts its first shard or its complete shard set.
- Imports explain their selection result. Chat/tool checks and hardware refresh
  are visible in the model library. Browsing and preference selection load no weights.
- Coding commands retain an OS-enforced local-only policy; there is no unrestricted
  fallback where that policy is unavailable. Original requests and verification
  requirements are preserved when context admission rejects a request.
