The SSD worker is a separate private backport. The ordinary inference resources are unchanged.

`node scripts/prepare-ssd-inference.mjs` builds it on macOS ARM64 with CMake and Apple Command Line Tools. `SSD_CMAKE` can select CMake. The source checkout and build stay in `.cache/ssd-engine`; no model is downloaded or loaded by this command. The script applies the tracked patch to a clean detached base checkout, embeds its SHA256, runs synthetic CPU fixtures, bundles portable libraries and retained source licenses, ad-hoc signs each native file, and inventories every byte. Use `--verify` to verify generated resources against the tracked source patch.

Base: d81235049384534c167caea52b85a694f6103d14 (0.6.0 / b11429).
Backported functional commits: 4260e460832f5e95c41d8b6d8b2aea98007df524, db5268ffac4c3ddacd7edcf62e78e3a1ba8d8191 (PR25294). The patch preserves pinned precision and per-layer expert APIs and adds local safeguards. It is not an upstream binary or an upstream-approved implementation.

Generated resource root: `resources/ssd-inference/darwin-arm64`. Executable: `worker/llama-server-ssd`; CPU and Metal share the same portable binary. The worker accepts only one local model/slot, authenticated loopback, two I/O workers, no mmap, no engine tools/web UI/downloads/MCP/speculation/adapters, audited Gemma4/Qwen3Next groups, and local APFS descriptors. `--ssd-require-streaming` rejects every partial/ordinary fallback; slots must fit the byte budget and be at least three times topK.

Policy flags: `--ssd-expert-cache-bytes`, `--ssd-budget-bytes`, `--ssd-resident-limit-bytes`, `--ssd-deadline-ms`; use `--moe-stream-io-threads 2 --load-mode none -np 1`. The initial deadline guards loading. Ready disarms it; `POST /ssd/control {"deadlineMs": ...}` arms each inference (max eight hours), and response completion clears it. `{"idle":true}` explicitly disarms an idle timer; `{"cancel":true}` settles the worker and cannot revive it. Control/status remain authenticated while loading. A request without an armed deadline is rejected. Shutdown bounds waits to ten seconds, with native process termination as protection against stalled filesystem/driver calls.

`SSD_STATUS` JSON is emitted before model loading and every two seconds. `GET /ssd/status` returns the same identity, expected/streamed groups, slots, validated I/O mode, allocation ledger, observed Darwin physical footprint and RSS, deadline state, and progress counters. The ledger guards large owned buffers (dense/cache/KV/recurrent/graphs/CPU workspace/staging/uploads/ggml arenas) before allocation and conservatively reserves 256MiB for variable driver/server/heap metadata overhead. Driver/framework allocations also appear in physical footprint. Sampling cannot guarantee an instantaneous OS memory cap or eliminate driver overhead. Physical footprint and RSS are assessed independently, never summed as separate unified memory.

Native fixtures: `llama-ssd-self-test cache` tests actual CPU `mul_mat_id` numerical equivalence, slot hits/eviction/raw byte preservation and waved masks; `ledger` tests allocation rejection/release, real boot footprint and idle deadlines; `cancel`/`deadline` must exit75. `metal` validates tiny cache reads/uploads on a native Metal device. Set `GGML_METAL_SHARED_BUFFERS_DISABLE=1` only for the synthetic private-upload test. These do not load a language model. Real model quality/task correctness is separate validation by the application.

The inventory also contains a separately verified `worker/llama-plan-ssd`, compiled from tracked `native-plan.cpp` against the same patched libraries. It reads model metadata and builds native graph shapes with `no_alloc=true`, `load_mode=none`, no inference or payload buffers. It includes tied-output/embedding duplication, actual KV/SWA/recurrent sizes, aligned cache sizes, native compute graph size, output allowance, two staging slabs, a conservative 64-thread CPU workspace bound and the unchanged 256MiB overhead reserve. `ledger.totalBytes` is the exact sum of steady components; `loadingDenseStagingBytes` and `loadingPeakBytes` separately report the whole-tensor staging required by CPU repacking. Real cache allocation follows dense loading, so these phases do not overlap. Nested repack/CPU allocations are charged once. Both phase peaks must fit the same allocation budget. The exact plan is bound to the worker patch, planner source, model digest (by the caller), and full profile; the application remeasures available RAM after the helper exits before admission. Planning does not establish model quality or successful weight loading.

Planner CLI is strict: `--model PATH --backend cpu|metal --ctx-size 4096 --batch-size 64 --ubatch-size 16 --output-tokens 1024 --cache-slots N --cache-bytes C --ssd-budget-bytes A --ssd-resident-limit-bytes T --deadline-ms 30000`. Unsupported/duplicate/unknown/missing arguments fail before model inspection. The maximum plan deadline is 30 seconds; SIGTERM/SIGINT request bounded cancellation. `SSD_PLAN` JSON reports source identity, exact profile and each budget component. CPU is the baseline; Metal remains a separate QA path until native validation. Cold payload is never mapped or allocated by the planner. Recurrent state and attention KV are reported separately for supported hybrid architectures.

The separately inventoried `worker/llama-hash-ssd` is compiled from tracked `native-hash.cpp` and uses the macOS system CommonCrypto SHA256 API, without initializing the engine or loading its libraries. Its strict CLI is `--file PATH --deadline-ms N --resident-limit-bytes LIMIT`; the deadline is 1–1,800,000 ms and the process limit 32–256 MiB. It requires a read-only local APFS regular descriptor, rejects symlinks, enables per-FD `F_NOCACHE` and disables read-ahead, and hashes sequentially through one 1 MiB buffer without mmap. It verifies device/inode/size/mtime/ctime before each chunk and after completion. `SSD_HASH` binds the complete digest/size/bytes read and descriptor fingerprint to source/patch identity; `SSD_HASH_PROGRESS` reports real bytes read and process measurements without paths or user content. Cancellation, deadlines, missing native RSS/physical-footprint/available-RAM monitoring, process limits, available RAM below 512 MiB, or observed critical pressure stop verification. Protection is sampled; it does not change system cache, swap, or other applications.

Only an unvalidated filesystem or explicitly unsupported uncached descriptor emits `SSD_HASH_FILESYSTEM_UNSUPPORTED`; ordinary import/download callers may choose their existing supported-file behavior for that case. SSD trial/load identity checks must fail closed without a native proof for every shard. Using uncached descriptors avoids deliberately warming the buffered model cache during integrity verification, but does not guarantee reclamation of pages cached by earlier readers or a larger measured trial budget. The application still refreshes hardware/available memory and applies the unchanged allocation/residency reserves after verification. No whole-model cache attribution or RAM savings is established by the small native helper fixtures.

`quantized-parity.cpp` is a separate read-only native validation fixture, excluded from the app inventory. Build it as C++17 against the patched `src`, `include`, and `ggml/include` headers and the inventoried `libllama.0`, `libggml.0`, `libggml-base.0`, and `libggml-cpu.0` dynamic libraries. Define `SSD_PARITY_PATCH_SHA256` to the exact manifest patch and set the library rpath to that resource directory. Invoke only after checking current available RAM/pressure and stopping overlapping app-owned trials: `quantized-parity --model PATH --verified-model-sha256 DIGEST --expected-patch-sha256 PATCH`. The caller must already have verified the full model digest; the fixture checks descriptors/file identity and records that supplied digest without claiming a second full-file hash.

The fixture surveys all30 Gemma4 routed groups and sequentially checks the first/last group of every distinct quantization/dimension/scale layout. It loads one ordinary CPU expert group at a time and uses the same 24-slot streaming cache, real quantized slabs and native CPU `mul_mat_id`, with the pinned input shapes (one broadcast lane for gate/up and eight per-expert lanes for down), original-ID scale gathers, hits, eviction/reload, full waves and a partial final wave. Allocation is bounded to900MiB, sampled residency to960MiB and execution to a shared five-minute deadline. A short hold permits fresh two-second resource samples. It does not create a language-model context or exercise routing, whole FFN/transformer outputs, whole-model reasoning, task quality, or Metal numerical parity. Successful representative comparisons do not establish universal numerical equivalence; sampled memory stops are not instantaneous hard caps.
